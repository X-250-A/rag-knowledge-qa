# 排序与查找算法

冒泡排序通过相邻元素两两比较并交换，让较大的元素像气泡一样逐渐浮到数组末尾。每轮确定一个最大值的位置，共需要 n-1 轮。它的平均和最坏时间复杂度都是 O(n 的平方)，且是稳定的排序算法。

选择排序每轮从剩余未排序的元素中选出最小值，放到已排序部分的末尾。它需要进行 n-1 轮，时间复杂度固定为 O(n 的平方)，但每一轮只交换一次，因此交换次数比冒泡少。选择排序是不稳定的。

插入排序把数组分成已排序和未排序两部分，逐个把未排序元素插入到已排序部分的正确位置，类似整理扑克牌。它平均和最坏是 O(n 的平方)，但最好情况下（数组已经基本有序）只有 O(n)，且稳定，适合数据量小或接近有序的场景。

快速排序采用分治策略，先选取一个基准（pivot），把数组划分成小于基准和大于基准的两部分，再递归地对两部分排序。它的平均时间复杂度是 O(n log n)，最坏（每次选到极值作基准）是 O(n 的平方)，是不稳定的算法，但由于常数小、缓存友好，通常是最快的通用排序算法。

归并排序同样采用分治，把数组不断对半拆分，直到每个子数组只剩一个元素，再两两合并有序子数组。它的时间复杂度稳定为 O(n log n)，是稳定的，但需要 O(n) 的额外空间来合并。

堆排序借助最大堆，先把数组构造成堆，再反复取出堆顶最大值放到数组末尾并调整堆。它的时间复杂度稳定为 O(n log n)，空间复杂度为 O(1) 原地完成，但因为它跳着访问元素，缓存不友好，且不稳定。

综合来看：对于一般场景，快速排序平均最快；对稳定性有要求时选归并排序；数据量很小或接近有序时插入排序非常高效；要求原地排序且不关心稳定性时堆排序合适。

二分查找针对已经排好序的数组，每次取中间元素与目标比较，根据大小关系排除一半区间。它的时间复杂度是 O(log n)，但前提是数据必须有序且支持随机访问，因此主要适用于静态、有序的数组。
