# 并查集

并查集是一种用于处理不相交集合的合并与查询问题的数据结构，主要解决动态连通性问题：给定一批元素，动态地判断任意两个元素是否属于同一个集合，并支持把两个集合合并。它的核心只有两个操作：查找（find）和合并（union）。

find 操作用于查找某个元素所属集合的代表元（通常是树根）。每个集合用一棵树表示，树根就是该集合的代表元，find 沿着父指针一直向上走到树根。union 操作把两个集合合并，做法是找到两个元素的根，然后把其中一个根接到另一个根下。

初始时每个元素各自成树。如果合并时始终把一棵树无脑接到另一棵树下，树可能退化成一条链，find 最坏退化为 O(n)。为此引入两项优化：按秩合并与路径压缩。

按秩合并（union by rank）在合并时总是把高度较低（秩较小）的树接到较高的树下，避免树变高。路径压缩（path compression）在 find 的过程中，把沿途经过的节点直接挂到根上，使后续查找更快。

两项优化同时使用时，find 和 union 的均摊时间复杂度近似为 O(1)，准确地说是一个增长极其缓慢的反阿克曼函数级别，在实际规模下可以视为常数。这是并查集效率极高、应用广泛的原因。

并查集与图遍历（如深度优先搜索或广度优先搜索）常被用来解决同一类连通性问题，但思路不同。图遍历每次查询连通性都要从起点出发遍历一遍，一次查询是 O(V+E)，适合处理静态图；并查集支持在线地动态合并与查询，每次操作近似 O(1)，适合元素集合不断变化的场景。

并查集的典型应用包括：朋友圈问题（判断哪些人属于同一个社交圈子）、岛屿数量（把相邻的陆地格子合并，最后统计集合个数）、以及 Kruskal 最小生成树算法中用并查集判断加入一条边是否会形成环。

需要留意的是，如果只使用按秩合并而不用路径压缩，单次操作是 O(log n)；只有两者配合才能达到近似 O(1) 的均摊复杂度。另外并查集只支持合并，不支持删除元素或拆分集合。
