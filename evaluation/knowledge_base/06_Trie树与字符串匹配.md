# Trie 树与字符串匹配

Trie 树（前缀树、字典树）是一种用于存储字符串集合的树形结构。根节点不存字符，从根到某个节点的路径上的字符拼接起来就是该节点对应的前缀，而从根到叶子节点的路径对应一个完整的字符串。共享相同前缀的字符串会共用路径上的节点，这是 Trie 节省空间的关键。

Trie 的基本操作是插入和查询。插入一个字符串时，从根出发逐个字符沿对应边前进，若边不存在就新建节点；查询时同样逐字符前进，若中途某条边缺失或到达的节点不是字符串结尾，则说明该字符串不存在。每个字符只被访问一次，因此插入和查询的时间复杂度都是 O(m)，其中 m 是字符串的长度。

这个复杂度只与字符串长度有关，与字符串集合的大小 n 无关，这是 Trie 最突出的特点。当字符串长度远小于集合规模时，Trie 的查询比逐条比较字符串快得多。

Trie 的核心价值在于前缀匹配。给定一个前缀，从根沿其字符走到对应节点，该节点子树中的所有字符串都以这个前缀开头。这一特性被广泛用于搜索引擎的自动联想（输入前缀提示候选词）和拼写检查，两者都依赖 Trie 快速找出某一前缀下的所有单词。

Trie 与哈希表常被拿来比较。哈希表查询单个字符串是 O(1)，但要支持前缀匹配只能逐个枚举所有键，效率很低；Trie 天然支持前缀查询。另一方面，Trie 是典型的空间换时间结构，节点数远大于字符串个数，字符集越大空间浪费越明显；哈希表对完整字符串的精确查找更快、更省空间。因此前缀相关的场景选 Trie，精确查找选哈希表。

KMP 算法解决的是单模式串匹配问题，其核心思想是主串指针不回溯：当模式串与主串在某个位置失配时，利用已匹配部分的信息把模式串向右滑动一段距离，主串指针不回退，避免重复比较。这一思想与 Trie 的多模式匹配恰好互补，Trie 负责同时匹配大量字符串，KMP 负责高效匹配单个模式串。

需要留意的是，Trie 的节点数可能与字符串总长度同量级，当字符集较大或字符串很短时空间浪费明显；判断一个字符串是否存在时，必须显式标记节点是否为某个字符串的结尾，否则会把一个字符串误判为另一个字符串的前缀。
