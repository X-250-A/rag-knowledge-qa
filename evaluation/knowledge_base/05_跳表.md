# 跳表

跳表（Skip List）是一种在有序链表基础上叠加多层索引来加速查找的随机化数据结构。普通有序链表查找元素必须从头逐个比较，时间复杂度是 O(n)；跳表每隔若干节点抽取一个组成上一层索引，再对索引继续抽取形成更高层，查找时先在高层稀疏索引中大步前进，接近目标后下降到底层，从而把复杂度降到 O(log n)。

跳表的查找过程像在多层道路上行驶：先在最顶层索引快速跳过大量节点，一旦发现下一个节点值超过目标，就下降一层继续前进，最终在最底层定位目标。每下降一层，搜索范围就缩小一层，越往下越接近目标节点。

插入一个新元素时，先执行同样的查找过程定位插入位置，把节点插入底层链表后，再通过随机方式决定该节点要向上提升到几层，并在每一层建立相应的索引指针。删除时则从包含该节点的每一层中把它摘除即可。

因为查找已经降到了 O(log n)，插入和删除又都以查找为基础，所以跳表的查询、插入、删除三种操作的平均时间复杂度都是 O(log n)，空间复杂度平均为 O(n)。

跳表与平衡二叉搜索树相比各有优劣。二者的查找、插入、删除都是 O(log n)，但跳表不依赖旋转等复杂的再平衡操作，代码实现更简单；跳表天然支持按区间高效地范围查询，而平衡树要中序遍历才能得到有序区间。代价是跳表需要额外的指针维护索引，内存开销更大。Redis 的有序集合就是用跳表实现的。

跳表的层数是随机决定的：生成新节点时，以二分之一的概率决定是否把它提升到上一层，直到失败为止。因此第 i 层的节点数约为总数的二分之一的 i 次方，总的索引空间期望约为 2n。这种随机化的层数选择取代了平衡树的严格平衡机制。

跳表刻意不追求严格平衡，因为维护严格平衡需要像 AVL 树那样在每次插入删除后做旋转调整，实现复杂。跳表用概率保证平衡：它不保证每一次操作都是 O(log n)，但出现退化、复杂度升到 O(n) 的概率极低，实际性能和平衡树相当，而实现简单得多。

需要留意的是，跳表要求元素支持排序比较，否则无法建立有序索引；随机数生成器的质量也会影响性能，如果随机数不均匀，索引可能失衡，查找退化为接近线性。
