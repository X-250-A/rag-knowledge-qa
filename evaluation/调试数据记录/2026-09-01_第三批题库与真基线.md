## 四、教训

- **交付验证必须看最终存储层**（chroma count/内容），不能只信 API 200 + 文档表 status=ready——"上游成功 ≠ 下游落库"
- **跑分不变 ≠ 无效果**：要先确认改动真的进入了被测系统（本次检索池根本没扩）
- **异常形态当场追**：Hit@5 掉到 0.091 这种"崩到地板"的结果反而是最快定位 user 归属错误的线索
- ID 生成策略要含全局唯一成分（uuid/user_id 前缀），依赖数据库自增 ID 做外部系统主键是隐患
